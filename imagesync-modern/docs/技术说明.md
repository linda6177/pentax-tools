# Image Sync · Modern UI（第二阶段：原生界面重构）

把 RICOH Image Sync **2.1.32**（`com.ricohimaging.imagesync`）的前端界面替换为一套重新设计的
原生 Android 界面，同时**完整保留原版相机通信核心**：BLE / Wi-Fi 连接、设备发现、PTP 图片传输、
实时取景、快门与拍摄参数全部继续由原版 Ricoh Wireless SDK 执行。

- 输入 APK：`D:\Download\OPPO\Image Sync.apk`
  - sha256 `00756f0c0474c7f6ac0271b817effadf15e92362d49eab9d86cd0d6bba639442`
  - minSdk 23 / targetSdk 36 / versionName 2.1.32
- 输出 APK：`dist\ImageSync-Modern-2.1.32.apk`（同包名、新签名、Sole launcher 为新界面）
- 不修改原版任何 dex / resources：新界面作为 `classes3.dex` 附加，`classes.dex`、
  `classes2.dex`、`resources.arsc` 与全部 2858 个原始条目保持逐字节一致（`test.py` 断言）。

## 与第一阶段（壳）的区别

| | 第一阶段 | 本阶段 |
|---|---|---|
| 首页 | 说明卡片 + 跳转原版 | 原生首页，实时连接状态 / 电量 / 最近拍摄 / 快捷操作 |
| 连接 | 只能跳原版 TitleActivity | 直接调用原版 SDK `detect(WLAN)` + `connect(WLAN)`；另保留官方向导处理蓝牙/NFC 配对 |
| 相册 | 跳原版 MainActivity | 原生三列网格 + 相机/本机切换 + 多选下载队列 + 进度 |
| 查看器 | 原版 ImageViewActivity | 原生全屏查看器：双击/双指缩放、滑动切换、下拉关闭、下载/分享 |
| 遥控 | 跳原版 ShootingActivity | 原生实时取景 + 点按对焦 + 快门 + 自拍计时 + 曝光参数底部面板 |
| 设置 | 说明卡片 | 原生设置页：相机信息、连接状态、传输说明、原版入口 |

所有相机操作通过 `CameraBridge` 汇聚到原版 SDK。

## 逆向分析结论（本阶段的主要依据）

完整证据与代码级说明见：

- `analysis/NOTES-CONNECT.md` — 连接生命周期、`SvApplication` 状态、Wi-Fi-only 检测路径
- `analysis/NOTES-GALLERY.md` — 相册列表/缩略图/下载协议、Scoped Storage 缺陷、本机媒体
- `analysis/NOTES-REMOTE.md` — 实时取景帧契约、快门/对焦状态机、设置规范化、线程模型
- `analysis/UIKIT-API.md` — 新界面内部 API 契约

关键事实（均为对原版产物静态分析所得，标注见 notes）：

1. **通信是 HTTP REST，而不是自定义二进制**。相机端点为 `http://192.168.0.1`
   （G900 SE 为 `192.168.1.1`），`GET /v1/props` 探测机型，`GET /v1/photos` 列表，
   `GET /v1/liveview` 返回 MJPEG，`POST /v1/camera/shoot` 拍照，`PUT /v1/params/*` 改参数。
2. **Wi-Fi-only 连接可用**：手机已连上相机热点时，`CameraDeviceDetector.detect(WLAN)` +
   `CameraDevice.connect(WLAN)` 即可完成连接，无需 BLE；这条路径取代了第一阶段“必须走原版向导”的限制。
3. **实时取景回调直接给完整 JPEG**：`CameraEventListener.liveViewFrameUpdated(device, byte[])`
   每帧一次、位于 SDK 工作线程；新界面在后台线程解码（RGB_565）后主线程换帧，避免原版主线程解码卡顿。
4. **快门是异步状态机**：`startCapture()` 立刻返回 `EXECUTING`，`captureComplete` 在 SDK 图像同步线程
   1–3 秒后才到达；`finishCapture()` 是空实现，停止拍摄必须用 `stopCapture()`。
5. **拍摄参数必须传“规范化对象”**：`setCaptureSettings()` 通过反射把实例匹配到 SDK 常量，
   因此只能回传 `getAvailableSettings()` 里的对象；新界面据此实现参数面板。
6. **原版下载在 Android 11+ 会静默失败**（目标 SDK 36 仍用 `Environment.getExternalStorageDirectory()`
   + `File` 复制，`IOException` 被吞）。新界面改为 **MediaStore（`Pictures/Image Sync`,
   `IS_PENDING`）** 发布，修复该缺陷。

## 第二轮修复（真机反馈）

1. **固件版本显示**：相机上报 `02.50`，界面统一显示 `2.50`
   （`CameraBridge.prettyFirmware()`，首页与设置页共用）。
2. **遥控参数无法调整 / 二级菜单拥挤**：拍摄参数面板重做为近全高底部面板，
   顶部“模式 / 曝光 / 画质色彩”分类切换；行点击进入**面板内二级取值页**（当前值高亮 + 勾选），
   不再堆叠横向 chip。模式页新增**照片/视频拍摄模式**（`setCaptureMode`，经相机规范化对象写入）
   与曝光模式；写入时行内 spinner，成功只重读该参数并交叉淡入，失败显示原因；
   参数缓存未就绪时显示“相机参数同步中…”+ 重试（`readSettings` 内部已做 3 次重试）。
3. **Dock 图标与刷新图标**：修正底栏图标按屏幕密度被重复缩放导致笔画过粗/显示不全的问题
   （线宽改为 24×24 图标坐标系内 1.75，随画布统一缩放）；重绘刷新图标为干净的圆弧+箭头。
4. **可切换主题色**：设置 → 外观 → 9 种主题色（默认**海蓝**，不再是系统紫色），
   含“跟随系统”（Android 12+ 壁纸取色）；切换立即重建界面，当前标签页保留。
5. **红外遥控集成**：遥控页新增“红外”入口（仅当手机具备红外发射器时显示），
   兼容 **PENTAX O-RC1**：快门释放、对焦近处、对焦远处；近/远键长按 2 秒后每 200 ms 连发、
   最长 30 秒，短按单步。协议为 38 kHz 载波 + 原厂单帧编码
   （13 ms/3 ms 头 + 6 位 MSB 数据 + 停止位 + 60 ms 尾），实现于 `IrRemote.java`；
   集成脚本会向二进制 manifest 插入 `android.permission.TRANSMIT_IR`（普通安装期权限，
   无需运行时申请），设置页还提供发射器状态与“发送一次快门测试”诊断。

## 第三轮修复（真机反馈）

1. **相册分段文字消失**：分段控件的滑动药丸设置了 `elevation`，在 API 21+ 上它会盖住同级文字
   （被提升的 View 后绘制），导致选中的“相机/本机”文字看不见。已去掉药丸 elevation，
   改用细描边表示选中态。
2. **红外遥控移入遥控栏顶部**：遥控页顶部新增 `WiFi 遥控 / 红外遥控` 双模式切换（滑动药丸 + 触感，
   状态持久化）。红外模式下不再需要 WiFi：独立深色面板提供 快门释放 / 对焦近处 / 对焦远处，
   近/远键长按 2 秒后每 200 ms 连发（最长 30 秒），并显示“连发中/发送中”；无红外发射器时显示说明。
   底部那排的“红外”小按钮已移除。
3. **旋转与更多动效**：旋转改为 300 ms 动画（同时插值旋转角与适配缩放，首次自动转向同样动画），
   旋转图标每次点按转动 90°；WiFi/IR 模式切换、顶栏与底部控件入场、状态胶囊都加入淡入+位移/交错动画。
4. **彻底屏蔽跳回原程序**：移除了所有 `launchConnectionWizard()` / `openLegacy()` 与 Intent 跳转
   （首页、相册空态、遥控未连接态、故障兜底页均已清理；连 `CameraBridge` 里未使用的向导入口也删除）。
   连接流程只剩：直接检测相机 Wi-Fi + “打开系统 Wi-Fi 设置”，不会离开本应用。
5. **设置页取消**：设置页整页删除（关于/传输等无法点击的卡片随之移除），底部导航变为
   首页 / 照片 / 遥控 三个入口。
6. **主题色无感切换**：主题色选择移到首页（顶部调色板按钮或“主题色”卡片）。
   切换时先对当前画面做快照，重建新主题界面后让快照 320 ms 淡出——视觉上是平滑溶解，
   不再有页面重载/闪动，也不重新创建 Activity。
7. 移除了设置页依赖的 `SettingsScreen` 类与相关入口；首页快捷卡片改为
   相册 / 遥控 / 检测连接 / 主题色。

## 第四轮修复（真机反馈）

1. **红外界面不再强制黑夜**：IR 页面、WiFi/红外切换器、状态胶囊、按键全部改用主题令牌
   （`t.background/surface/surfaceAlt/text/muted/accent/onAccent/success/hairline`），
   浅色模式即浅色界面；只有相机取景区域与闪光/网格等叠加层保持黑色。
2. **主题切换闪退修复**：旧的无感切换在重建前未把 `currentTab` 复位，导致 `selectTab`
   提前返回、随后对新屏幕调用 `onHostResume()` 时视图尚未创建（空指针）。
   现在 `rebuildForTheme()` 会先复位 tab、释放旧屏幕（移除相机监听）、重建外壳、
   再恢复 tab，并用像素快照 320 ms 淡出完成无感过渡。
3. **昼夜模式自动跟随 + 手动切换**：首页“主题色”卡片内新增 跟随系统 / 浅色 / 深色 选择
   （默认跟随系统；系统昼夜切换时 Activity 重建并保留当前标签页；手动模式持久化）。
4. **红外面板人体工学**：控制区下沉到底部——快门释放为 112 dp 圆形强调色大按钮（最靠近拇指），
   对焦近处/远处为 78 dp 圆形 tonal 按钮置于其上方；顶部只保留紧凑的标题/状态/提示；
   底部留出安全区，不被 dock 遮挡。
5. **长按连发修复**：原实现被 ScrollView 父容器拦截手势导致连发失效。
   现在近/远键的触摸处理 `requestDisallowInterceptTouchEvent(true)`，
   短按发一帧；按住 2 秒触发 LONG_PRESS 并进入连发，200 ms 一帧由独立 Handler 驱动
   （不等异步回调，用发送中标志跳过重叠帧），30 秒上限；抬起/滑出/切模式/离开页面即停止。
6. **相册分段框改为主题色**：原白色分段容器改为 `accentSoft` 轨道 + `accent` 选中药丸
   （选中文字用 `onAccent`），与整体配色一致。

## 第五轮修复（真机反馈）

1. **顶部 WiFi/红外切换绘制重做**：旧实现用 `setX` + 每帧改 LayoutParams，导致选中药丸
   左缘发直、宽度/内缩与文字不齐。现改为固定 40dp 轨道 + 3dp 内缩；指示器宽度一次算好
   （内容宽/2），动画只改 `translationX`（260ms），两个等宽文字标签居中，选中/未选中文字
   颜色用 ArgbEvaluator 同步过渡；圆角=高度一半，任何宽度下都不会被裁切。
2. **对焦长按连发加入连续触感**：按住 2 秒触发 LONG_PRESS 后，连发期间每 200ms 在按下的
   对焦键上触发 CLOCK_TICK 触感；抬起/滑出/切模式/30 秒上限立即停止，不会拖尾。
3. **红外切换黑边修复**：新增全屏 `t.background` 背景层，切换第一帧即不透明，WiFi 取景层
   在其下方淡出；IR 面板以 “透明度 + 24dp 上移” 300ms 进入，返回时先恢复取景层再淡出
   背景层，任何阶段都不会露出黑边/黑闪。快速来回切换会取消全部过渡动画，避免叠加。
4. 相册状态视图加固：避免快速切换时状态层停在透明 0；骨架屏对比度提高（浅色背景不再“空白”）。

## 第六轮修复（真机反馈）

1. **相册“未连接提示消失”修复**：从“本机”切回“相机”时，之前的加载/错误标志可能残留，
   使状态机停在骨架屏或错误页而不再显示未连接提示。现在切回相机且未连接时会清空
   `cameraLoading/cameraError` 并强制重新计算状态；相机断连事件也会做同样清理。
2. **相册未连接动画**：Wi-Fi 空态新增呼吸光晕、两圈向外扩散的信号波纹，以及一颗沿圆周
   缓慢环绕的强调色小点；离开页面时统一停止动画，避免后台耗电。
3. **连发启动时间缩短**：红外对焦长按触发时间由 2 秒改为 **0.5 秒**（200ms/次、30 秒上限不变），
   IR 提示文案同步更新为“长按对焦键 0.5 秒开始连发”。
4. **红外切换动画改为页面统一语言**：去掉上下浮动，WiFi↔IR 现在使用与标签页一致的
   「交叉淡入淡出 + 18~24dp 水平位移 + 0.985→1 轻微缩放」；主题色背景层仍从第一帧起可见，
   全程无黑边/黑闪，快速来回切换会取消全部过渡动画。
5. **相册切换按钮绘制修复**：相机/本机分段指示器改为真正的胶囊（圆角=高度一半），
   宽度在布局时一次算好、动画只改 `translationX`，不再出现平边或非椭圆端。

## 第七轮修复（真机反馈）

1. **相册 Wi-Fi 动效被裁切**：空态动画容器由 136dp 增至 204dp 并关闭 clipChildren，
   光晕/波纹的放大范围与环绕小点都有足够空间，动画可以完整播放不再被窗口裁掉。
2. **红外→WiFi 左侧黑边**：把取景层（全屏黑色）与界面 chrome 分离——全屏层只做淡入淡出、
   强制不水平位移（平移黑色画面会把黑色边缘拖进画面）；只有顶栏/底部控件等小面积 chrome
   保留 +24→0dp 的进入位移。主题色背景层一直保持不透明，直到 WiFi 画面完全淡入（290ms）
   后才在 300ms 处开始淡出，任何一帧都不会露出黑色。
3. **红外对焦按钮连发时被裁切**：IR 面板的 ScrollView / 内容列 / 对焦行全部关闭
   clipChildren 与 clipToPadding，对焦行四周加 8dp 内边距；连发放大改为 1.06x
   （每边仅约 2.3dp，远小于 8dp），78dp 圆形按钮在连发过程中始终完整显示。
4. **快门释放最大震感**：新增 `Haptics` 工具，直接走 Vibrator 最大振幅（255/70ms），
   并在集成时向 manifest 写入 `android.permission.VIBRATE`。WiFi 快门与红外快门都改为
   单次最大震感；长按对焦触发用中等震感，连发期间每 200ms 一个短震动，松手立即停止。
5. **相册相机/本机切换改为统一形式**：去掉标签上的 ripple/按压灰度层，改为与
   WiFi/红外切换一致的形式——胶囊指示器 260ms 平移 + 两个标签文字颜色 240ms
   ArgbEvaluator 交叉渐变（原实现颜色是瞬变，看起来“没有连续动画”）。

## 第八轮修复（真机反馈）

1. **本机空态加动效**：本机相册为空时使用的照片图标现在也播放与相机 Wi-Fi 空态相同的动画
   （光晕呼吸、两圈扩散信号波纹、强调色小点环绕），两种空态观感一致。
2. **相机/本机切换动效修复**：指示器改为独立的 `ValueAnimator`（300ms）驱动
   `translationX`，并加入“动画进行中禁止布局回弹”的保护（此前刷新/布局变化会把指示器
   直接吸附到目标位置，看起来像没有动画）。标签文字颜色仍与指示器同步做 240ms 渐变，
   与 WiFi/红外切换完全同款：胶囊滑动 + 颜色交叉渐变。

## 第九轮修复（真机反馈）

1. **底部导航顺序调整**：交换“遥控”和“照片”，现在为 首页 / 遥控 / 照片；
   对应的屏幕工厂、图标、点击区域与左右滑动顺序同步更新。
2. **支持左右滑动切换页面**：在内容区域横向滑动（位移 >56dp、水平分量 >1.9×垂直分量、
   700ms 内完成）即可切到上/下一个页面，复用与点击底部导航完全相同的滑动过渡；
   查看器等全屏 overlay 打开时、或页面过渡进行中不会误触发。
3. **空态动画在刷新/连接期间保持**：相机未连接或本机相册为空时点击“刷新/快速连接”，
   不再立刻换成骨架屏把动画吞掉；空态插图（光晕、波纹、环绕点）会持续播放，
   按钮下方显示“正在读取/正在扫描/正在通过 Wi-Fi 连接相机…”的进度提示，
   只有真正拿到照片或相机连接成功后才切换页面。

## 第十轮更新（LUT / 查看器 / 设置 / 底部栏）

1. **查看器 LUT 功能**：照片查看器顶部新增 LUT 按钮（调色板图标 + “LUT” 小字），点击打开
   主题化底部面板：
   - 「无 · 原图」；
   - 内置 LUT —— `D:\Desktop\LUT_33` 下 17 个 V21 显示 sRGB LUT（构建时打包进 APK 的
     `assets/luts/*.cube`，ZIP 压缩）；
   - 自定义 LUT —— 通过系统文件选择器添加任意 `.cube`，URI 授权持久化保存，下次启动仍可用。
   选择后后台线程从**原始解码图**应用 LUT（不叠加、不修改原文件），显示“正在应用 LUT…”，
   结果缓存并在切换/清除时回收；工具栏图标高亮、底部信息追加 LUT 名称；切换图片自动复位。
   相机照片与本机照片都支持。
2. **查看器高倍缩放闪烁修复**：改为单个 `ScaleType.MATRIX` ImageView + 自持一个 Matrix；
   双指按焦点缩放并限制在 1x–4x（到达边界时忽略多余增量，不会来回抖动）；不再混用
   view 缩放属性、手势中不重置矩阵；双击/回弹用动画；双指松开时重新锚定触点消除跳变；
   适配滑动关闭与翻页（仅原始比例时启用）。

## 第二十三轮更新（HEIC 保存格式）

设置页新增「保存格式」：**JPEG**（默认）/ **HEIC · 压缩**。

  MIME `image/heic`，仍保存在 `Pictures/Image Sync`）；同时自动扫描该目录下已有的 JPEG
  并逐张转换为 HEIC（通知栏显示进度 4311），转换成功后删除原 JPEG；失败会回滚并计数，
  不会产生重复文件。
- 体积/质量平衡点：按约 **1 bit/pixel** 自适应码率（2400 万像素约 2.2MB，比常见 8–12MB
  JPEG 小 60–70%），编码分辨率上限 4096、下限 3000 长边；EXIF 方向已烘焙进像素。
- 不支持 HEVC 的系统（或 API < 28）会自动回退为 JPEG，并提示改回 JPEG；
  编码偶尔失败时同样回退保存原 JPEG，不会丢照片。
- HEIC 编码基于系统 MediaCodec(HEVC) + MediaMuxer(MUXER_OUTPUT_HEIF) 单帧封装，
  优先 ByteBuffer(YUV420Flexible)，必要时退回输入 Surface 绘制路径。

## 第二十五轮更新（HEIC 编码器适配）

错误 `HEIC编码失败(3680x2456): ... IllegalArgumentException` 并不是像素太大（3680×2456 仅约 900 万），
而是所选 HEVC 编码器不支持该尺寸/对齐或颜色格式。本轮改为按编码器能力自适应：
- 枚举所有 `video/hevc` 编码器，读取 `CodecCapabilities/VideoCapabilities`，把目标尺寸限制到
  `supportedWidths/supportedHeights` 与宽高对齐要求内（不足时按约 0.9 收缩直到 `isSizeSupported`），
  编码器上限小于目标时自动缩放并标注“已按编码器上限缩小”；
- MediaFormat 只写入编码器真正支持的键（码率、帧率 1、I 帧间隔 0），VBR 仅在支持时设置，
  不再强制 profile/level；
- 每种编码器依次尝试「输入 Surface → YUV420Flexible → NV12 → I420」，只使用 capabilities 中
  声明的颜色格式，第一个成功即停止；
- 失败信息细化到“编码器名 / 颜色格式 / 目标尺寸 / 支持尺寸与对齐 / 具体失败阶段与异常”，
  下一次真机报告可以直接定位是哪一步不兼容；
- 迁移结果通知会附带“N 张按编码器上限缩小”，转换仍保持“体积不减小则跳过”和 JPEG 回退。

## 第二十六轮更新（HEIC 18KB 损坏文件修复）

上一版转换出的 HEIC 只有约 18KB 且无法打开，原因是 MediaCodec 编码循环只写入了编码器配置
数据、没有写真正的一帧（样本数为 0）。本轮修复并加入强校验：
- 编码循环严格排空到 `BUFFER_FLAG_END_OF_STREAM`，处理 `INFO_OUTPUT_FORMAT_CHANGED`，
  只丢弃 codec-config 缓冲，所有有效输出缓冲都写入 muxer，并统计样本数与输出字节数；
- 码率提高到 `clamp(像素 × 2, 8–48 Mbps)`（按编码器支持范围裁剪），优先 HEVC
  Main Still Picture profile，配置被拒时自动去掉 profile 重试；
- **输出校验**：文件必须 ≥20KB 且能被 `BitmapFactory`/`ImageDecoder` 正常解码、尺寸与目标一致；
  不满足就拒绝该策略并换下一种，最终失败则回退保存原 JPEG，绝不写入坏 HEIC；
- **删除原图前必须校验**：新 HEIC 编码通过 + MediaStore 插入后回读大小 >20KB，才删除原 JPEG；
- 已损坏的小 HEIC（<20KB/无法解码）若有对应 JPEG 会被自动修复替换；无法解码的坏 HEIC
  不会被删除，仅计数失败；通知栏会显示“修复损坏 HEIC N 个”。

`com.ricoh.camera.sdk.*`、`androidx.*` 或桩类。

## 设备测试清单（建议顺序）

1. 安装后冷启动：首页、底栏、切换动画、暗色模式、手势导航安全区。
2. 已连接相机热点 → 首页「检测相机 Wi-Fi」→ 状态变为已连接，显示机型/电量。
3. 首次配对 → 「官方连接向导」完成 BLE + Wi-Fi 配对，返回后首页状态正确。
4. 相册：相机列表加载、缩略图、多选下载 → 系统相册出现 `Pictures/Image Sync` 文件；
   本机相册加载与查看。
5. 查看器：缩放、双击、左右切换、下拉关闭、下载/分享。
6. 遥控：实时取景出图、点按对焦、快门、自拍 2s、参数面板改 ISO/快门/曝光补偿后相机侧生效。
7. 断网/关相机：界面进入未连接态，无崩溃；重连后恢复。

## 已知限制

- BLE 首次配对、NFC 连接仍走原版向导界面（协议复杂、无法在无设备条件下重写并验证）。
- 下载进度在部分机型上粒度较粗（SDK 以块回调），界面使用不确定进度兜底。
- 实时取景方向默认自动判断并提供手动旋转；不同持机方式可微调。
- 视频录制、包围曝光等高级拍摄模式未提供专用 UI，可通过原版入口使用。
- 新界面为 Java + framework 组件，未引入 AndroidX，因此没有 Material 组件库的共享元素转场；
  屏幕过渡、缩放、底部面板均为自绘动画实现。
- “本机”相册受原版 manifest 限制：APK 未声明 `READ_MEDIA_IMAGES`（原版 targetSdk 36 也没有），
  Android 13+ 上 MediaStore 只返回本应用可见的媒体。这与原版行为一致，界面会提示原因；
  Android 12 及以下可授予 `READ_EXTERNAL_STORAGE` 浏览更完整。
- 外观支持 跟随系统 / 浅色 / 深色 三种模式（首页“主题色”卡片内切换，手动模式会记住）；
  “跟随系统”下系统昼夜切换会重建界面并保留当前标签页。
- 红外遥控依赖手机自带红外发射器（`ConsumerIrManager`）；无发射器的手机不会显示该入口。
  相机必须处于“遥控拍摄”模式；对焦微调需在机身/镜头上关闭 AF（与 O-RC1 官方说明一致）。
- 全屏查看器位于被系统栏内边距裁切的外壳 overlay 层内，极端边到边（Android 15 强制 edge-to-edge）
  情况下状态栏/导航栏区域可能出现一条外壳底色；查看器会把系统栏临时染黑以减轻视觉差异。
