# K-70 / KP 工程模式入口文件名核验

日期：2026-10-21。全部为电脑端离线操作，未连接相机、未读写存储卡。

## 结论

| 机型 | 固件 | cpu | public | 工程模式文件名 | 原公开值 |
|---|---|---:|---:|---|---|
| K-70 | v1.16 / v1.15 / v1.11 | 586 | 78370 | **00078370.586** | 00077770.524（镜像内不存在） |
| KP | v1.31 / v1.10 | 581 | 78380 | **00078380.581** | 00078389.581（镜像内不存在） |

## 方法

1. 从 RICOH IMAGING 官网下载官方固件包（`k70_v116.zip`、`k70_v111.zip`、`k70_v115.zip`、`kp_v131.zip`、`kp_v110.zip`）。
2. 用严格 LZ 帧解码器解出镜像（无恢复、无猜测字节；每个包都是 811 帧全部解出）。
3. 在镜像中定位 ROM 元数据记录：magic `HOKKTKIYHTNTMU`，随后是小端 u32 `cpu`、u32 `public`，再后 4 字节为 `[次版本, 主版本, 0x0B, 0x14]`。
4. 固件内文件名模板为 `C:\%08ld.%03ld`（`ModeSetOperation.cpp` 字符串表），因此文件名 = `{public:08d}.{cpu:03d}`。

记录位置：主镜像 `0x12FFF00`，镜像副本 `0x2FFF00`（两处数值一致）。

## 交叉验证

同一规则在四个文件名已经确认的机型上成立：

| 机型 | 记录 | 已知文件名 | 一致 |
|---|---|---|---|
| K-1 | 562 / 77970 | 00077970.562 | 是 |
| K-1 II | 597 / 78400 | 00078400.597 | 是 |
| K-3 III | 582 / 78420 | 00078420.582 | 是 |
| KF | 619 / 78520 | 00078520.619 | 是 |
| K-70 | 586 / 78370 | 00077770.524（公开） | **否** |
| KP | 581 / 78380 | 00078389.581（公开） | **否（8 位段不同）** |

## 为什么改 K-70 的文件名

`00077770.524` 在 K-70 v1.11 / v1.15 / v1.16 三份官方镜像中都不存在：全镜像搜索既没有 `77770` 这个 u32，也没有 `(524, 77770)` 相邻记录。而 `00078370.586` 由固件自身的元数据直接给出，且同一位置的记录在四个已确认机型上与公开文件名完全一致。因此 v1.3 把 K-70 默认方案改为 `00078370.586`，旧值只作“备用方案”保留，避免误改后无法回退。

KP 同理：公开值 `00078389.581` 的 3 位段与固件一致（581），8 位段不一致；固件给的是 `78380`。

## 命令与校验值

两份固件内均能找到：

- `OPEN_DEBUG_MENU`、`SCRIPT_EN_MODE EN`、`SCRIPT_EN_MODE DIS`、`DEBUG_MODE EN`、`DEBUG_MODE DIS`
- 10 字节 DEVELOP 校验值 `07 01 2C 1F 10 03 1E 16 05 2D`
- `startup.ttl` 脚本路径与 `DevelopersMode` / `eSubScriptMode` 字段

两份固件内都**没有** `ForcedActivation` / `CustomImage ForcedActivation*` 命令，因此 K-70、KP 不能通过 TTL 脚本启用四季滤镜，本版不把它们列入四季机型。

## 复现

```powershell
python 提取工程模式文件名.py k70_v116.zip
python 提取工程模式文件名.py fwdc232b.bin
```

脚本会打印镜像 SHA-256 与每条 ROM 元数据记录；核验时用的哈希见 `核验记录.json`。

## 边界

- 未实机验证菜单是否出现；若标准方案无菜单，先核对相机固件版本，再试备用文件名方案。
- 本方法只适用于带 `HOKKTKIYHTNTMU` 元数据记录的镜像；K33 早期镜像不是这种格式，需按 `K33工程菜单核查` 的方法处理。
- 没有验证菜单内部的各项调试操作，也没有生成刷机包。
