# 宾得工模写卡工具 v1.3 更新记录

日期：2026-10-21
范围：只改 K-70、KP 的工程模式入口文件名与对应教程；其他机型方案、四季滤镜脚本、写卡引擎不变。

## 一、结论

| 机型 | v1.2 | v1.3 | 依据 |
|---|---|---|---|
| K-70 | 00077770.524（公开内容重建） | **00078370.586**（固件元数据核验） | 官方 k70_v116 / v1.15 / v1.11 ROM 元数据 cpu=586、public=78370 |
| KP | 缺项（未提供文件包） | **00078380.581**（固件元数据核验） | 官方 kp_v131 / v1.10 ROM 元数据 cpu=581、public=78380 |

两机型的 `DEVELOP.MOD` 仍是 v1.2 已用的 10 字节原厂校验值：

```
07 01 2C 1F 10 03 1E 16 05 2D
```

## 二、怎么得到的

1. 从 RICOH IMAGING 官网下载官方固件包：

   - K-70：[k70_v116.zip](https://www.ricoh-imaging.co.jp/english/support/digital/firmware/k70_v116.zip)（另有 v1.15、v1.11 对照）
   - KP：[kp_v131.zip](https://www.ricoh-imaging.co.jp/english/support/digital/firmware/kp_v131.zip)（另有 v1.10 对照）

2. 把包内的 `fwdc234b.bin` / `fwdc232b.bin`（各 18,880,016 字节）用严格 LZ 帧解码器解出镜像（19,922,928 / 19,922,920 字节，811 帧全部解出，无恢复、无猜测字节）。

3. 镜像尾部有 ROM 元数据记录，magic 为 `HOKKTKIYHTNTMU`，随后两个小端 u32 为 `cpu`、`public`，再后 4 字节为 `[次版本, 主版本, 0x0B, 0x14]`：

   | 机型 | 记录偏移 | 镜像副本 | cpu | public | 版本字节 |
   |---|---|---|---:|---:|---|
   | K-70 | 0x12FFF00 | 0x2FFF00 | 586 | 78370 | `10 01 0B 14` → v1.16 |
   | KP | 0x12FFF00 | 0x2FFF00 | 581 | 78380 | `1F 01 0B 14` → v1.31 |

4. 固件内文件名模板是 `C:\%08ld.%03ld`（`ModeSetOperation.cpp` 的字符串表），所以文件名 = `{public:08d}.{cpu:03d}`。

## 三、为什么敢改（交叉验证）

同一规则在四个文件名已经确认的机型上完全对上：

| 机型 | 记录 | 已知文件名 |
|---|---|---|
| K-1 | 562 / 77970 | 00077970.562 ✔ |
| K-1 II | 597 / 78400 | 00078400.597 ✔ |
| K-3 III | 582 / 78420 | 00078420.582 ✔ |
| KF | 619 / 78520 | 00078520.619 ✔ |

K-70 / KP 用同一套记录格式与查询顺序，得到上面的新值。

原公开值对不上：

- K-70 的 `00077770.524` 在 v1.11 / v1.15 / v1.16 三份镜像里都不存在（全镜像既没有 `77770` 这个 u32，也没有 `(524, 77770)` 相邻记录）。
- KP 的 `00078389.581` 只有 3 位段 581 与固件一致，8 位段在 v1.10 / v1.31 镜像里不存在。

因此 v1.3 把固件值设为默认方案，旧公开值保留为“公开旧文件名（备用）”方案，标准方案无效时可以直接换，不需要回滚到 v1.2。

## 四、命令与功能边界

两份固件内都能找到 `OPEN_DEBUG_MENU`、`SCRIPT_EN_MODE EN`、`SCRIPT_EN_MODE DIS`、`DEBUG_MODE EN`、`DEBUG_MODE DIS`，以及 `startup.ttl` 与 `DevelopersMode` / `eSubScriptMode` 字段，所以每个机型除标准入口外还给了“开启/关闭脚本模式（备选）”方案。

两份固件内都没有 `ForcedActivation` / `CustomImage ForcedActivation*` 命令字符串，**所以 K-70、KP 不能通过 TTL 脚本启用四季滤镜**，本版也没有把它们加进四季机型。四季功能区仍是 K-1、K-1 II/K12、K-3 III（彩色版）、KF 四款，共 136 个方案；这部分脚本代码原样保留。

## 五、验证

- 编译：`源码\编译.ps1`（csc，.NET Framework 4.0），输出 230,400 字节 exe。
- 内建自测：`宾得工模写卡工具.exe --self-test 验证\自测结果.txt` → PASS，36 个机型条目、38 个工程方案（v1.2 为 31）、4 个四季机型、136 个四季方案；全部使用临时目录，未写存储卡。
- 界面截图：`验证\v1.3_主界面.png`，标题与提示已改为 1.3，K-70 / KP 已从“缺项”改为可写卡。

## 六、没做的

- 没有实机验证菜单是否真的出现（没有相机操作）。若标准方案无菜单，先核对相机固件版本，再试备用文件名。
- 没有验证菜单内部的调试操作，也没有生成刷机包。
- K-3 III Monochrome 仍是缺项（未核实）。

## 七、复现

`固件核验\` 目录里有：

- `说明.md`：完整方法与证据表
- `提取工程模式文件名.py`：本地解码官方 zip/bin，打印镜像 SHA-256 与每条 ROM 元数据记录 → 文件名
- `核验记录.json`：两份固件的哈希、偏移、数值、交叉验证与限制

```powershell
python 固件核验\提取工程模式文件名.py k70_v116.zip
python 固件核验\提取工程模式文件名.py fwdc232b.bin
```

## 八、补充更正（同日）

经用户确认，K-3 III、K-70、KF 的工程模式进入方式**不是**打开卡仓，而是：

> 装好卡 → **关好卡仓** → **按住 MENU 不放** → 开机

v1.3 已同步修正这三款的程序内教程、手动包 `使用教程.txt` 与 `K33工程菜单核查/README.md`。

- K-1 / K12 仍为：按住 MENU + 卡舱门打开时开机。
- KP 尚未单独确认进入方式，教程按同代机型写成“关好卡仓 + 按住 MENU”优先，未进入时再试卡仓打开。
